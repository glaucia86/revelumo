# Getting help

Revelumo is a development preview. There is no public release or installer yet, and the current CI matrix is not a promise of end-user platform support.

You can ask questions and report problems in **English, Brazilian Portuguese, or Spanish**.

## Where to start

- **Run the project:** follow the [README source setup](README.md#how-to-try-it), including Node.js 24, Electron installation, and platform caveats.
- **Understand current behavior:** check [implemented features and limits](README.md#what-you-can-do-today) and the [development and verification notes](README.md#development-and-verification).
- **Report a bug or suggest a feature:** search [existing issues](https://github.com/glaucia86/revelumo/issues), then use the appropriate [issue form](https://github.com/glaucia86/revelumo/issues/new/choose).
- **Ask a usage or development question:** if the documentation and existing issues do not answer it, open a blank issue from the same issue chooser with a clear title and the smallest useful example.
- **Contribute a change:** see [CONTRIBUTING.md](CONTRIBUTING.md).
- **Report a suspected vulnerability:** read [SECURITY.md](SECURITY.md). Do not include vulnerability details in a public issue.

## Make a report useful and safe

Include the commit you tested (`git rev-parse HEAD`), OS/version/architecture, Node and npm versions, the command or workflow that failed, steps to reproduce, and expected versus actual behavior. State whether you used development mode or the locally packaged app. A short, relevant log excerpt is usually more useful than a whole catalog or system dump.

Use synthetic images and fresh test catalogs. Remove personal photographs, usernames and personal file paths, secrets, private metadata, and EXIF/GPS coordinates from logs and screenshots before posting. Do not upload a personal catalog or original photo collection. If you cannot reproduce the problem without sensitive material, describe the limitation without attaching that material.

Issue forms collect report information; they do not run commands, upload your local files automatically, or start a support session.
